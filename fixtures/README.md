# Fixtures

These are **synthetic** cases. They exercise the evidence, correlation and
report pipeline. They are not observations of a real deployment and cannot
claim confirmed proof statuses.

## `619-correlated`

Built by:

```bash
python fixtures/build_619_correlated.py
```

It contains a producer request, a consumer request, `state_publish` and
`state_consume` lab-trace events on the same invented worker PID, and a
nonce-free synthetic timeline. The assessors return:

```text
CVE-2026-109618  EXPOSED_BUILD
CVE-2026-109619  PRODUCER_CONSUMER_CORRELATED
```

`PRODUCER_CONSUMER_CORRELATED` is the highest status a fixture may reach. The
case is `environment.kind=fixture`, `environment.synthetic=true`, and every
evidence record has `synthetic=true`. `STALE_STATE_CONFIRMED`,
`AFFECTED_PATH_CONFIRMED` and `CODE_EXECUTION_CONFIRMED` are refused by the
assessors.

Rebuild the report offline:

```bash
python php2shell_scanner_v4.py report fixtures/619-correlated \
    --out fixtures/619-correlated/report-rebuilt
python php2shell_scanner_v4.py verify fixtures/619-correlated
```

`report/` is the report generated by the builder; `report-rebuilt/` is the
offline reconstruction. They should show the same verdicts and a PASS hash
check.
